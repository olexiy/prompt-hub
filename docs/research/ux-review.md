## Reviewer summary

1. The core loop works and feels like GitHub: create a project or folder, write a prompt with `{{vars}}`, see a live preview, copy, keep versions, diff, restore. Restore makes a new version, so nothing is lost. Primer conventions, the `/` search shortcut and confirmation dialogs are handled well.
2. The biggest problems are trust and state. An **archived public project returns 404 to visitors**, although Settings promises it "stays reachable by its URL". **Make public** happens in one click with no confirmation. **Cancel** in the editor drops unsaved edits without asking.
3. The versioning model is unclear to a new user. The primary **Save** silently overwrites the live version and "Save as new version" is secondary. Diff only compares a version with the one before it, so "compare an old version with the current one" cannot be done. Variable defaults can only be set in Edit mode, not when the prompt is created.
4. Feedback is thin. There are no toasts after save, move, duplicate, delete, restore or make public. The dashboard empty state still says "Creating projects comes with the next update" in all three languages. A failed project import shows its error under the filter box.
5. Mobile is mostly fine, with no overflow on read pages. Two layouts break: **Version history** puts one character per line, and the **edit form** overflows horizontally (DE). The terminology mixes "tag" and "topic", and RU/DE translate "topic" as «тема»/«Thema», which collides with the visual theme setting.

## Works well

- Slug auto-generation from the name, including Cyrillic transliteration ("Портреты" → `portrety`), with a live URL preview under the field.
- Variables: live detection while typing in Edit (Cyrillic names like `{{фон}}` work). The read view has a live preview with highlighted substituted values. Defaults are applied to the copy. The warning "Empty variables stay as {{…}} in the copy: subject, style" is very clear.
- Restore is non-destructive (creates v4 "Restored v1"). The "live" badge shows the current version. "Only you see the history" sets expectations.
- Destructive actions (delete version, prompt, folder, project) have Primer confirmation dialogs. Project delete requires typing the name. The Danger zone texts explain consequences well, including what a public visitor can see.
- Duplicate dialog explains "The copy starts with the current version as v1, in the same folder".
- Tag input normalises input ("Film Grain" → `film-grain`) and sorts chips. The project Topics field explains the rules.
- Meta editor: free key/value fields with clear naming rules.
- Header search: the `/` shortcut, highlighted matches, project/folder path per result, helpful "Try fewer words or the start of a word" empty state.
- Import of a single .md: H1 becomes the title, and there is a review form before creating. Accept filter on the file input.
- 404 page is friendly and shows the path. The visitor view of a public project is clean and read-only, and Copy works for anonymous users.
- en/ru/de UI strings are essentially complete (apart from the stored "Restored" label and terminology). Light and dark themes both render cleanly. No JavaScript errors in the console on any page; the only console errors were 404/401 network responses from intentional not-found visits.
- Read-only pages (dashboard, project, prompt) have no horizontal overflow at 375px.

## Not tested / limits

- Real clipboard: the embedded browser denies `clipboard-write`, so success was verified by stubbing `navigator.clipboard`. Success and fallback paths both work.
- Zip export download and a valid zip import (no downloads allowed). A single-file import was simulated by injecting a `File` into the file input.
- Narrow-width EN/RU edit form (F14) was only measured in DE.
