## Baseline mechanics (#23)

| Mechanism        | Where                                                          | Notes                                                                                                                                                                                                                                                                                                             |
| ---------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Headers, API     | `apps/api/src/security/headers.ts`                             | `default-src 'none'` CSP, HSTS, nosniff, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, Permissions-Policy, COOP/CORP, `Cache-Control: no-store`. Set after the handler, so errors get them too.                                                                                                        |
| Headers, web app | `apps/web/public/_headers` (copied to `dist/` by Vite)         | Strict CSP: `script-src 'self'`, `style-src 'self'`, no `unsafe-inline`/`unsafe-eval`, `frame-ancestors 'none'`; same companion headers; immutable caching for hashed assets.                                                                                                                                     |
| Rate limiting    | `apps/api/src/security/rate-limit.ts`, `wrangler.jsonc`        | Workers Rate Limiting binding, keyed by `cf-connecting-ip`. `AUTH_LIMITER` 10/min on sign-in, reset, recovery session, password change. `WRITE_LIMITER` 60/min on every non-GET. 429 + `Retry-After: 60`.                                                                                                         |
| Body limits      | `apps/api/src/security/validate.ts`                            | 256 KiB per request body, 413 above.                                                                                                                                                                                                                                                                              |
| Validation       | `parseJson(c, schema, message)` in `validate.ts`               | Every body goes through a Zod schema; failure is a 400 with the route's own message, never Zod details.                                                                                                                                                                                                           |
| Errors           | `apps/api/src/security/errors.ts`                              | `onError`: clients get `{ error, requestId }` only; 500 details go to the log under the same id (Cloudflare ray id when present).                                                                                                                                                                                 |
| Logs             | `apps/api/src/security/log.ts`                                 | One JSON line per event; keys like token/password/cookie/email are masked, emails and JWTs are scrubbed from strings. Security events (#61): `auth_sign_in`, `auth_sign_in_failed`, `auth_link_refused`, `auth_password_changed`, `rate_limited`, `origin_refused` — user id and/or client IP, never the address. |
| CSRF             | `apps/api/src/auth/middleware.ts` (`sameOrigin`)               | Non-GET must carry our `Origin` and `application/json`; cookies are `SameSite=Lax`.                                                                                                                                                                                                                               |
| Tests            | `apps/api/test/security.test.ts`, `e2e/tests/security.spec.ts` | Headers on success/404/401/400 and on HTML; 429 after the limit; 400/413 bodies; no internals in 500s; app runs under the CSP with no console errors.                                                                                                                                                             |

## Known gaps and decisions

- **Rate limits are per IP and per Cloudflare location** (the binding is eventually consistent). Per-account protection against credential stuffing comes from Supabase Auth's own limits and Turnstile (Phase 2).
- **`cf-connecting-ip` is trusted** because Cloudflare overwrites it at the edge; locally and in tests it is missing (key `unknown`) or set by the test.
- **Trusted Types** (`require-trusted-types-for 'script'`) are not enabled yet; check Primer compatibility before turning them on.
- **`/security-review`** runs before every production deploy that touches auth, authorisation or input handling.
- **No "change password" with the old one yet.** Signed-in users change it through "Forgot password"; a settings form with the current password comes with account settings.

## Review before the MVP release (#61, 2026-10-25)

Manual review of `apps/api/src` (middleware, auth, every project, public, search and archive route), the input schemas in `packages/core` and the web app's DOM and redirect handling.

| #   | Severity | Finding                                                                                                                                                                                                                                                                                                                   | Outcome                                                                                                                                                                                                      |
| --- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Medium   | `POST /api/auth/session` took any valid access token and set it as the session; `POST /api/auth/password` worked in any session. A link `/auth/callback#access_token=…` with the attacker's tokens signed a visitor into the attacker's account unnoticed (login CSRF), and a hijacked session could change the password. | Fixed: `/session` replaced by `/link` (names the account, no cookies); `/password` takes the link session in the body, requires a fresh email-link `amr` entry, and signs in only after the password is set. |
| 2   | Medium   | No security events in the logs (ASVS V16).                                                                                                                                                                                                                                                                                | Fixed: events listed above.                                                                                                                                                                                  |
| 3   | Low      | Two parallel version deletes could both pass the "last version" check and leave a prompt without versions.                                                                                                                                                                                                                | Fixed: prompt row locked, count rechecked in the transaction.                                                                                                                                                |
| 4   | Low      | Dev-only advisories in zod/undici (daily OSV scan).                                                                                                                                                                                                                                                                       | Fixed in #77 (pnpm overrides); production was not affected.                                                                                                                                                  |

Checked without findings: owner scoping and 404s on every project route (handle and owner id both checked), public routes (PUBLIC + not archived only, history and `note` hidden, versions routes owner-only), search (only own projects; tsquery built from letters/digits only, all values bound as parameters), zip import (server takes only a validated JSON bundle, own 8 MB limit, one transaction), cookies and CSRF, JWT verification, error bodies, CSP, no `innerHTML`/`dangerouslySetInnerHTML`, no open redirects.
